    System Help & Documentation
    About Network Diagnostics

    A robust, fault-tolerant network diagnostic dashboard designed for troubleshooting network issues across home, office, and managed environments. Built using Python, Flask, SQLite, and Scapy.

    Should you have any issues or suggestions on improvements, please log them via github. I will try to get to them and respond to it.

    GitHub Repository
    Setup & Launcher Scripts

    The application uses several automated wrapper scripts to handle environment setup automatically across different operating systems:

    For the most part these have the same functionality but are tailored for each OS. The main difference is that on the Mac OS install script there is no option to enable a hotspot on the device.

    These same scripts can be used to fully remove the application as well.

    Windows-Installer.ps1 PowerShell script: Requests administrator privileges, checks for Python (downloads and installs it from the python website if missing), downloads or updates project files from GitHub into the user's profile directory, and prompts for dedicated test device features (such as generating standalone, disablecleanup, and webport configuration files, or setting up a Windows Wi-Fi Mobile Hotspot). It also configures user-login startup, individual desktop/start menu shortcuts using the custom app logo, and hands off execution to the setup script.
    Linux-Installer.sh: Automatically detects the Linux distribution, installs required system packages (such as Python 3, venv, pip, git, and network-manager), downloads or updates project files from GitHub into the user's home folder, and prompts for dedicated test device options (creating configuration triggers and setting up an optional Wi-Fi Hotspot via NetworkManager). It also handles optional systemd background services, desktop shortcuts with custom logo integration, and launches the environment supervisor.
    MacOS-Installer.sh: Verifies macOS prerequisites (installing Python 3 and Xcode tools if missing), downloads or updates project files from GitHub into the user's home folder, and offers dedicated test device options to write configuration triggers. It also manages background launchd boot agents, builds a native macOS .app bundle in the Applications folder with a high-resolution custom icon converted from the project logo, and executes the setup script.
    setup_env.py: The core supervisor script. Manages virtual environments, installs Python requirements, downloads/updates the Speedtest CLI, enforces file permissions across the OS, and monitors the main application for crashes.
    Dashboard Basics
    Live Status Dot: Indicates that the dashboard is actively communicating with the backend server.
    Refresh Network Info: Forces an immediate OS-level query to update the physical adapters and active IP data without waiting for the background cache.
    Table Sorting: All data tables across the dashboard are dynamically sortable. Simply click on any column header (like Name, IP, Mac, or Date) to instantly toggle ascending or descending order.
    Touch Mode (Hand Icon): Increases the size of buttons, checkboxes, and table rows to make the interface much easier to tap on tablets and mobile devices.
    Theme Toggle (Sun/Moon): Switches the application between Light and Dark mode. This preference is saved to your browser automatically.
    Speed Test Tool: Runs an immediate bandwidth test (Download, Upload, and Ping) against Ookla Speedtest servers. You can select the active connection type (e.g., Ethernet vs Wi-Fi) and type a custom location name which will be stored alongside the result in your history.
    Network Adapters

    This tab displays the active state of the physical hardware attached to your system.

    Hide / Unhide Selected: Select adapters using the checkboxes to hide them from the main view. This is useful for removing virtual adapters, VPNs, or loopbacks that clutter your dashboard.
    Hide No-MAC: Instantly filters out software-based interfaces that lack a physical MAC address.
    Show Hidden: Temporarily reveals adapters you have previously hidden. A green "Unhide Selected" button will appear allowing you to restore them permanently.
    Edit / Pin Adapter (Gear or Pencil Icon): Click the adapter name or the gear icon to open its settings. From there you can:
    • Rename the adapter.
    • Pin as Primary: Locks the dashboard header (Router IP, DNS, and Traffic Speeds) exclusively to this adapter's statistics.
    • Lock Wi-Fi Scanner: If the adapter supports Wi-Fi, you can force the system to exclusively use it for airwave scanning, preventing drops on your primary connection.
    Network Scanning

    Manage devices connected to your Local Area Network via ARP mapping and ICMP sweeps.

    Scan (New Scan): Performs a deep sweep of the active subnet to discover connected devices, checking for common open services (like HTTP, SSH) and resolving manufacturer names. This scan attempts to match against previous networks in your database automatically.
    Continue Scan: Resumes scanning the currently loaded network. To save time, this mode skips deep-port-checks on devices that were previously detected as offline.
    Split Scan: Runs a scan but saves the result as a completely independent network profile in the database, breaking it away from the current one.
    Isolated Scan: Runs a fresh scan but intentionally blocks the system from attempting to merge or match the results with any past historical data.
    Device Customization & Comments: Clicking on a device's Name or Comment cell opens the metadata editor. You can assign a custom name, manually set the vendor, and write multi-line global notes. These details automatically follow the device's MAC address across any network it connects to.
    Remove Selected / Offline: Permanently deletes the selected (or fully offline) devices from the active network's historical database.
    Network Scan History -> Merge: Check two or more networks in the history table and click "Merge". You will be asked to choose a "Main" network. All devices and history will be bundled into the main network, and the duplicates will be deleted.
    Auto-Match Toggle (Network History): Clicking the network icon () in the Actions column allows you to disable or enable whether future "New Scans" are allowed to merge into that specific profile.
    Wi-Fi Scanning

    Analyze local airwaves and historical Access Point data.

    Adapter Dropdown: Select which hardware to use. Choosing "Auto" will instruct the system to intelligently scan across ALL of your un-hidden Wi-Fi adapters simultaneously to merge the most comprehensive signal data (e.g., merging 2.4/5GHz results with a newer 6GHz adapter).
    Scan Wi-Fi: Triggers the OS to query nearby airspace. Note that this often disrupts active Wi-Fi connections momentarily while the radio listens for beacons.
    Auto-Logging: Every time you press Scan, the results are automatically saved to the database. You can rename the scan or add comments in the "WiFi Scan History" tab.
    Wi-Fi Comments & Expanding Notes: You can click the pencil icon next to any SSID in the active scan or global history to add a global comment. In the active scan view, long multi-line comments are neatly tucked away—just click the dropdown arrow to expand and read them!
    Global Wi-Fi History: An aggregate list of every single unique SSID your system has ever seen, including how many times it was detected and the date it was last seen.
    Other Tools
    DNS Lookup: Enter a domain name (like google.com) and the system will attempt to resolve its primary IP Address. The result is logged alongside the network you were connected to at the time.
    Ping Tool: Enter an IP or Domain. The system will send 4 ICMP echo packets to test reachability, measuring latency and packet loss. Results are logged to the database.
    Log Annotations: You can add context to your DNS and Ping logs by clicking the pencil icon to attach a network name and comments. These comments are fully preserved when exporting your logs to CSV.
    Record Protection (Padlock Icon): Clicking the padlock on any historical log (DNS, Ping, Networks, Wi-Fi) locks the record. A locked record will be protected and ignored when you execute bulk database cleanups via the Settings tab.
    Settings & Maintenance
    Create Local Backup: Generates an instant snapshot of your `.db` file in the backend `backups` folder. The system will automatically prune older backups based on predefined quotas to save disk space.
    Database Maintenance (Cleaning): The "Old > X Days" buttons permanently wipe historical logs and inactive devices that exceed that age limit. Items you have manually "Locked" (Padlocked) will survive this process.
    System Updates: Ensure your 'Update Channel' is set to Stable. Clicking "Check for Updates" compares your core application files against the GitHub repository. It will list the changes and handle the download, installation, and server restart automatically.
    App Preferences (Logging): "Full Diagnostic Logging" writes every backend action to a file for troubleshooting. "Disable All Logs" prevents the backend from writing to disk entirely (useful for Raspberry Pi SD Cards).
    Concurrency & Workers: Adjusts the ThreadPool executors. Increasing Scan Workers makes Network Scans faster, but requires more CPU power. If the dashboard freezes or crashes frequently during scans, reduce these numbers.
    Power Controls & Seamless Restarts: "Restart App" cleanly reboots the Python server. On macOS and Linux, the application uses an in-place process replacement, meaning it will seamlessly restart without asking for your sudo/admin password again! "Shutdown App" kills the server and background supervisor completely. If Dedicated Server Mode is active, you will also see options to physically Reboot or Shut Down the host machine OS.
    Advanced Configuration Files

    You can change advanced system settings or trigger emergency recovery actions by creating blank files (with no file extension) in the same folder as your app.py script.

    webport: Write a number (e.g., 8080) inside this file. On the next startup, the dashboard will switch to this port and delete the file.
    standalone: Create this blank file to enable Dedicated Server Mode. This unlocks the dangerous "OS Reboot" and "OS Shutdown" buttons in the Settings tab.
    disablecleanup: Create this blank file to completely disable the folder isolation safety checks. The setup script will always install/run in the current directory, regardless of other foreign files present.
    passwordreset: Create this blank file if you are locked out. On the next startup, the system will disable authentication, clear your passwords, and delete the file.
    cleardatabase: Warning: Create this blank file to perform a complete, irrecoverable factory wipe of your SQLite database on the next startup.
    reinstall: Warning: Create this blank file to trigger a complete wipe of the application directory. The supervisor will re-download the latest production files from GitHub and reinstall all dependencies from scratch.
    dev: Create this blank file to forcefully switch the application to the "Development" update channel on the next boot.
